# Design review — P1 UX bugs (2026-07-03)

Source: `docs/Bugs.xlsx` (raw list filed by UX dev "Codex" after an end-to-end new-user walkthrough).
Scope of this review: the **P1** rows only. P2 / P3 / no-priority rows are deferred to a later session.

This report states each issue, its root cause, and the planned change **for team review before any screen code is edited**. Reports like this live under `docs/design/reviews/` from now on.

---

## 1. Login — hardcoded "Welcome back to Acme Corp." (Bugs.xlsx row 2)
- **Issue:** The login page greets everyone with a fictional tenant name, "Acme Corp".
- **Root cause:** The sub-line is a literal string in the login screen. There is no real tenant to name before a user has logged in.
- **Planned fix:** Replace it with a neutral, brand-correct greeting that doesn't invent a company name.
- **Screen ref:** `frontend/src/features/identity/Login.tsx`; mockup `screens/S-02-login.html`.

## 1b. Login — email field defaults to sarah@acme.com (Bugs.xlsx row 3, re-prioritised P2 → P1)
- **Issue:** The login page's email field arrives pre-filled with `sarah@acme.com`; the user has to clear it before typing their own email.
- **Root cause:** The email field is initialised with sample data.
- **Priority note:** Filed P2, re-prioritised to **P1** on team request (it's the sibling of row 2 on the same Login screen and should ship with it).
- **Planned fix:** Start the email field empty with a placeholder hint (`you@company.com`), matching the signup form.
- **Screen ref:** `frontend/src/features/identity/Login.tsx`; mockup `screens/S-02-login.html`.

## 2. Signup — real-looking default values (Bugs.xlsx row 5)
- **Issue:** The signup form arrives pre-filled with "Sarah Chen", "sarah@acme.com", "Acme Corp". A new user has to clear each field.
- **Root cause:** The form fields are initialised with sample data instead of starting empty.
- **Planned fix:** Start every field empty and show grey **placeholder** hints (example name / email / workspace) instead of pre-filled real-looking values.
- **Screen ref:** `frontend/src/features/identity/Signup.tsx`; mockup `screens/S-01-signup.html`.

## 3. Navbar — "Payment Gateway v2" shown before any project exists (Bugs.xlsx row 6)
- **Issue:** Right after first login, before the user has created anything, the top bar's project switcher shows a fake project, "Payment Gateway v2".
- **Root cause:** The top bar falls back to a sample project name when the user has no projects yet.
- **Planned fix:** When there are no projects, show a neutral "No project yet" state instead of a fabricated name.
- **Screen ref:** `frontend/src/components/AppShell.tsx`.

## 4. Create Project — name field pre-filled with "Payment Gateway v2" (Bugs.xlsx row 8)
- **Issue:** The create-project form pre-fills the project name with the sample "Payment Gateway v2".
- **Root cause:** The name field is initialised with sample data.
- **Planned fix:** Start the field empty with a placeholder hint.
- **Screen ref:** `frontend/src/features/setup/CreateProject.tsx`; mockup `screens/S-09-create-project.html`.

## 5. Project Profile — Tech stack box too small (Bugs.xlsx row 11)
- **Issue:** The Tech stack field is a single-line box; a realistic multi-line stack list (see the reference paste in the sheet) doesn't fit.
- **Root cause:** Tech stack is rendered as a one-line input sitting in a two-column row, unlike the other long-form fields which are multi-line boxes.
- **Planned fix:** Make Tech stack a full-width, multi-line box (like Coding standards / Constraints) so a full stack list fits comfortably, with a placeholder example.
- **Screen ref:** `frontend/src/features/setup/ProjectProfileEditor.tsx`; mockup `screens/S-10-project-profile.html`.

## 6. Get Started flow — dead-end after creating a project (Bugs.xlsx row 12, Design Issue)
- **Issue:** The Get Started checklist promises 4 sequential steps (Create project → Connect machine → Invite team → Connect integrations). But creating a project drops the user on Project Profile, and after saving there they have no way back to the checklist to do steps 2–4.
- **Root cause:** No screen returns the user to the checklist. The checklist is only reachable by manually typing its URL, so the flow dead-ends after step 1.
- **Team decision (asked & confirmed):** Keep the checklist as the **hub**; every step returns to it. Wireframe reviewed and approved — see `docs/design/reviews/get-started-flow-wireframe.md`.
- **Planned fix (full loop, steps 1–4):**
  - After **saving the Project Profile**, return to the checklist (step 1 now ✓).
  - On **Connect Machine**, **Invite Team**, and **Integrations**, show a persistent "Back to Get started" link while setup is incomplete.
  - The checklist already auto-detects completion (project exists / machine checked in / team invited), so ticks appear on return with no new backend state.
- **Screen refs:** `SetupChecklist.tsx`, `ProjectProfileEditor.tsx`, `ConnectMachine.tsx`, `UsersInvites.tsx`, `Integrations.tsx`; mockup `screens/S-05-setup-checklist.html`.

## 7. Connect Machine — hardcoded `https://app.acme.com` (Bugs.xlsx row 15)
- **Issue:** The serve command in Connect Machine used a hardcoded fake URL.
- **Status:** **Already fixed in an earlier session.** The command now builds its URL from the configured API base; a repo-wide search for `app.acme.com` returns nothing. Verified only, no new change.
- **Screen ref:** `frontend/src/features/identity/ConnectMachine.tsx`.
