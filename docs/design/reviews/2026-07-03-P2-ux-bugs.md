# Design review — P2 UX bugs (2026-07-03)

Source: `docs/Bugs.xlsx` — the P2 rows. Issue → root cause → planned change per row, per standing
practice. Follows the P1 batches (`2026-07-03-P1-ux-bugs*.md`).

Team decisions (AskUserQuestion): include the two P2 enhancements (r4, r9); scope r30 as a
**bounded** sweep of the main in-app screens (exclude brownfield/code-intel, deferred).

Guardrails: UI-only changes; no tenant-isolation/RLS/gate logic touched; capabilities not vendors;
brownfield/code-intel screens left alone.

Root causes below were confirmed against the live stack (tenant `Edven`: 1 admin user, project
`Medslot`, one revoked invite).

---

## r16 — Connect Machine shows two spinners (Bug)
- **Issue:** After generating a token, two loaders appear next to "Waiting for first check-in…".
- **Root cause:** `ConnStatus state="waiting"` already renders its own spinner; `ConnectMachine.tsx`
  passes a second `<Spinner/>` as its child.
- **Fix:** Remove the child spinner; keep the one `ConnStatus` draws.

## r20 + r31.2 — Hardcoded "Acme Corp workspace" (Bug)
- **Issue:** The Users & Invitations (Workspace Admin) subtitle hardcodes "Acme Corp"; it should be
  the real workspace name.
- **Root cause:** Literal string in `UsersInvites.tsx`.
- **Fix:** Use `currentUser.tenant.name`. Sweep other real-screen "Acme Corp" literals (the pre-auth
  Accept-Invite screen keeps a neutral fallback since no tenant is known yet).

## r31.1 — Registered/invited users not shown until the Invite drawer opens (Bug)
- **Issue:** The admin's own account (and invitees) don't appear in the table; opening the Invite
  drawer reveals them "in the background."
- **Root cause:** `UsersInvites.tsx` shows the "It's just you so far" empty state whenever
  `list.length <= 1 && pendingInvites.length === 0`. With just the admin (and a non-pending invite),
  that hides the table; opening the drawer changes the view away from "empty", so the table renders.
- **Fix:** Show the table whenever there's at least one row to display (the admin always is one);
  reserve the empty state for a genuinely empty list.

## r24 — Artifacts search & filter don't work; filters have no options (Bug)
- **Issue:** The search box and Phase/Type/Status selects on the Artifacts registry do nothing and
  the selects only contain "All".
- **Root cause:** `ArtifactsRegistry.tsx` renders those controls with no state/handlers and no
  options.
- **Fix:** Wire search (client-side over type/phase) and Phase/Type/Status filters; populate the
  select options from the artifacts in view (+ phase catalog), humanised via `phaseLabel`.

## r33 — Phases & Runs offline state doesn't match the wireframe; humanise phases (Bug)
- **Issue:** When the companion is offline the screen differs from the S-18 wireframe, and phase
  names should be human-readable.
- **Root cause:** When offline the Runs panel still renders `sampleRuns` (demo data) instead of the
  wireframe's "No runs yet" empty state, because `view === "offline"` isn't treated as "no-runs".
- **Fix:** When offline with no real runs, show the "No runs yet" empty state; align the offline
  phase-picker to the wireframe; phase labels already go through `phaseLabel`.

## r7 — Get-started shows "Create your first project" already ticked (Bug)
- **Issue:** Right after first login the dashboard's Get-started panel shows a ✓ on "Create your
  first project" even though none exists.
- **Root cause:** The Dashboard new-project panel hardcodes step 1 as `vstep--done` (✓).
  (`SetupChecklist` itself is correct — signup creates no project/membership, so it computes step 1
  as not-done.)
- **Fix:** Render step 1 in the new-project panel as the active, not-done step.

## r4 — Placeholders in all forms (Enhancement)
- **Fix:** Add sensible `placeholder`s where missing across the auth / create-project / invite /
  profile forms.

## r9 — Greenfield/brownfield explainer text → tooltip (Enhancement)
- **Issue:** The create-project page shows a long "Greenfield starts from a blank profile.
  Brownfield opens onboarding…" sentence; the reporter wants a tooltip on the track instead.
- **Fix:** Remove the sentence; surface the same text as a help tooltip on the track selector.
  (Copy only — no brownfield orchestration touched.)

## r30 — Universal sweep: humanise underscores, make hardcoded values dynamic (Bug, bounded)
- **Fix:** Across the main in-app screens, humanise any remaining raw underscore phase/role/status
  renders and replace obvious hardcoded/demo strings (workspace name, sample identifiers) with real
  data. Much of this is already covered by the P1 work and the rows above; this row cross-references
  them. Excludes brownfield/code-intel screens (deferred).
