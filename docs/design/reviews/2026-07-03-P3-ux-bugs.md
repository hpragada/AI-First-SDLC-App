# Design review — P3 UX bugs (2026-07-03)

Source: `docs/Bugs.xlsx` — the P3 rows. Issue → root cause → change per row. Follows the P1/P2
batches. Root causes confirmed against the live stack.

Team decision (AskUserQuestion): for r32, "onboarding complete" = **project + machine** (inviting a
team stays optional); the link-only change is accepted even though the Setup checklist still lists
the invite step.

Guardrails: UI-only; no tenant-isolation/RLS/gate logic touched.

---

## r10 — Project profile shows "✓ Saved · v1" / "Saving will create v2" on a never-saved project (Bug)
- **Issue:** Right after creating a project, the profile page's top badge reads "✓ Saved · v1" and the
  form footer reads "Saving will create v2", even though nothing has been saved.
- **Root cause:** `GET /projects/{id}/profile/` returns 404 when no profile exists yet, so
  `profile.data` is undefined and `?? 1` fabricates version 1 in both the saved badge and the
  "Saving will create v{n+1}" hint. The first real save actually creates v1.
- **Fix:** Treat a missing profile as version 0 / not-saved: the badge shows "Draft · not saved yet"
  until the first save, and the dirty hint reads "Saving will create v1".

## r14 — Token / command copy button doesn't work (and is hard to see) (Bug)
- **Issue:** On Connect Machine, the Copy button next to the enrollment token (and the command
  blocks) does nothing.
- **Root cause:** `TokenReveal` and `CmdBlock` render a `Copy` button with no `onClick`.
- **Fix:** A shared `CopyButton` that writes to the clipboard (with a legacy fallback) and shows a
  brief "Copied!" confirmation; used by both `TokenReveal` and `CmdBlock`, with clearer styling.

## r32 — "← Back to Get started" persists after onboarding (Bug)
- **Issue:** The return link keeps showing on Connect Machine / Invite / Integrations even after the
  user has finished setting up.
- **Root cause:** `SetupReturnLink` hides only when `hasProject && hasMachine && hasTeam`, and
  `hasTeam` needs a *second accepted user* — a solo developer never satisfies it, so the link nags
  forever.
- **Fix:** Hide the link once the user has a project and a connected machine (team invite optional),
  per the team decision.

## r13 — Why is `/api/runners/` polled continuously on every screen? (Clarification)
- **Answer / root cause:** It's companion-liveness polling. `useRunners(true)` refetches every 4 s;
  react-query dedupes by the `["runners"]` query key, so it's a single request per interval, not one
  per component. It became global because the P2 fix put the live companion status pill in the
  always-mounted `AppShell`.
- **Change:** Give `useRunners` a configurable interval and let the always-mounted shell poll gently
  (~15 s), keeping the fast 4 s cadence on Connect Machine / Phases & Runs where liveness matters.
  This cuts the background churn on ordinary screens by ~4×.

## r19 — Nav/sidebar hardcoded (4 notifications, companion "ready", default Gates/Clarifications) (Bug)
- **Status:** Already fixed by the P1 work (dynamic Gates/Clarifications counts + notification bell,
  hidden when zero) and the P2 work (the companion pill in both the sidebar and top bar now reflects
  the real runner status). Verified live and recorded here for completeness; no new code beyond
  confirmation.
